## DDL and schema discovery

- **`dbDelta()`** resolves schema scopes, splits string input on semicolons, applies query filters, and uses case-sensitive regexes to route `CREATE TABLE`, `CREATE DATABASE`, `INSERT INTO` and `UPDATE`. It keeps the last CREATE per table, attempts `DESCRIBE` with errors suppressed, and leaves CREATE queued if the describe result is empty. For an existing table it captures the parenthesized body, splits it by newline and parses each field/index line. It lowercases column keys and normalizes PRIMARY, UNIQUE, FULLTEXT, SPATIAL and ordinary index definitions. It rebuilds catalog index definitions from `SHOW INDEX`, compares them while ignoring prefix lengths, and retains the desired subpart on new index definitions. `wordpress-develop-7.1.5/src/wp-admin/includes/upgrade.php:2936–3070`, `wordpress-develop-7.1.5/src/wp-admin/includes/upgrade.php:3075–3163`, `wordpress-develop-7.1.5/src/wp-admin/includes/upgrade.php:3269–3347`
- **Generated ALTERs** are `CHANGE COLUMN name full_definition`, `ALTER COLUMN name SET DEFAULT 'literal'`, `ADD COLUMN field_definition` and `ADD index_definition`. The default diff specifically recognizes quoted literals. Standalone drops and a general constraint or nullability diff are absent. The type diff avoids narrowing text/blob families and conditionally ignores integer display widths. `$execute = false` skips final execution after catalog inspection. The return value describes planned changes, with no check of individual `query()` results in the execution loop. `wordpress-develop-7.1.5/src/wp-admin/includes/upgrade.php:3205–3266`, `wordpress-develop-7.1.5/src/wp-admin/includes/upgrade.php:3338–3357`
- **Installer and upgrade helpers.** `make_db_current()` calls `dbDelta()` and prints messages. `make_db_current_silent()` calls it without printing. `maybe_create_table()` uses an escaped `SHOW TABLES LIKE` and exact table equality, and `maybe_add_column()` checks `DESC` column zero. After submitting opaque caller DDL both repeat their existence checks. The optional `install-helper.php` defines alternate `maybe_create_table()` (`SHOW TABLES` enumeration) and `maybe_add_column()` if missing, plus `maybe_drop_column()` and `check_column()`. `drop_index()` tries both the base and 25 numbered suffix names. `add_clean_index()` drops before adding. `maybe_convert_table_to_utf8mb4()` inspects column and table collations, then emits `ALTER TABLE ... CONVERT TO CHARACTER SET ...` if eligible. `wordpress-develop-7.1.5/src/wp-admin/includes/upgrade.php:2684–2826`, `wordpress-develop-7.1.5/src/wp-admin/includes/upgrade.php:3372–3395`, `wordpress-develop-7.1.5/src/wp-admin/install-helper.php:42–220`
- **Direct ALTER sites.** There are 37 literal `$wpdb->query("ALTER TABLE ...")` sites, all in `includes/upgrade.php`. Six are in historical single-site upgrade routines, five in `upgrade_network()`, four in generic index/charset helpers, and 22 in `pre_schema_upgrade()`. The four generated ALTER forms bring the total of static ALTER source sites to 41. The [SQL path inventory](data/R-002-ddl-paths.csv) gives each clause, table and owning function. It also records nine literal DROP TABLE sites (eight historical and one network uninitialization), the two bundled SimplePie PDO MySQL CREATEs, the dynamic DDL sinks and related maintenance calls. `wordpress-develop-7.1.5/src/wp-admin/includes/upgrade.php:1108–1215`, `wordpress-develop-7.1.5/src/wp-admin/includes/upgrade.php:1516–1561`, `wordpress-develop-7.1.5/src/wp-admin/includes/upgrade.php:1850–1856`, `wordpress-develop-7.1.5/src/wp-admin/includes/upgrade.php:2104`, `wordpress-develop-7.1.5/src/wp-admin/includes/upgrade.php:2271`, `wordpress-develop-7.1.5/src/wp-admin/includes/upgrade.php:2610–2826`, `wordpress-develop-7.1.5/src/wp-admin/includes/upgrade.php:3739–3792`, `wordpress-develop-7.1.5/src/wp-includes/ms-site.php:835`, `wordpress-develop-7.1.5/src/wp-includes/SimplePie/src/Cache/MySQL.php:90–99`

## Method/reproduction

```sh
wp_ref=../../reference/wordpress-develop-7.1.5

  --output docs/research/data --candidates --facade
```

The scanner reads 1,869 PHP files under `src/`, expands the declared index subpart literal and extracts column/default/key definitions. The scope excludes tests, JS, Gutenberg and the SQLite integration. It scans DDL keywords, reconciles each candidate with its source and adds reviewed dynamic sinks and selected install/upgrade DML from `tools/research/R-002/sql-review.tsv`. Counts represent source sites or definitions. Loops, hooks and arbitrary caller SQL can expand at runtime. `identity_sensitive=yes` marks statements that create or change identity schema, carry identity values/sentinels, or rely on generated identity state, and `context` denotes dynamic SQL or identifiers whose role depends on the caller.

**Manual validation and confidence.** Inspected all 77 raw keyword hits, exceeding the 30-hit sampling minimum. Two accepted hits are bundled SimplePie PDO MySQL DDL, so treating the keyword scan as WordPress-core-only would yield 9/77 (11.7%). Reviewed all 37 direct ALTER hits in context, with 0/37 false positives in that narrower class. Confidence is high for declared schema, literal SQL sites and exact stored-revision gates, medium for logical-reference interpretation and caller-dependent identity sensitivity, and low for completeness of indirect SQL from dynamic dispatch or hooks.
